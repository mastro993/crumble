# Remote transcription, after the user agrees to send the audio

A Recording can be transcribed by a remote Model as well as by Apple's SpeechAnalyzer on the Mac: any server that speaks OpenAI's audio transcriptions, which covers OpenAI itself and Whisper servers. Audio is the most private thing Crumble keeps, so before a Recording's audio first goes to a remote Model, Crumble asks, and remembers the answer for that Model on that server. Each Note says who made its Transcript.

## Rules

- **The trait**: `crumble_transcribe::Transcriber`, now that transcription has a second implementation (ADR 0006 waited for it). `transcribe(&self, dir, locale, progress) -> anyhow::Result<Vec<Segment>>` blocks, so callers run it off the main thread; `provider()` and `model()` say what made the Transcript. Its error is a sentence a user can act on. `progress` is `FnMut(f32) + Send`, as Apple's bridge calls it from a Swift thread while the caller waits. The implementations are `Apple`, which wraps the bridge, and `OpenAiCompatible { base_url, api_key, model }`. Downloading Apple's speech model stays a separate step the UI runs before `Apple` transcribes, so it can show its own progress.
- **Shared Providers and HTTP**: `crumble-remote` holds the `Provider` enum (`apple`, `claude`, `openai`), `runs_locally`, `base_url` (the address checks both Transcriber and Summarizer make before sending), `host`, `without_userinfo` (an address as errors and logs show it), `post`/`post_json` (`ureq` 3, 10-minute timeout, every status returned), and `failure`, which maps HTTP statuses to sentences. `crumble-summarize` and `crumble-transcribe` both use it. It is a crate of its own because neither of those two should depend on the other, and copying the helpers would let their error sentences and the local-or-remote rule drift apart. It needs no Swift and no `unsafe`.
- **Each track separately**: `mic.aac` and `system.aac` are uploaded one after the other, so the "You" and "Others" labels stay exact without diarization, and their segments are merged with the same pure `merge` Apple's Transcripts use.
- **The request**: `POST {base_url}/audio/transcriptions` as `multipart/form-data` with `model`, `response_format=verbose_json`, `timestamp_granularities[]=segment`, `language` (ISO 639-1, `en` for `en_US`) and `file`, plus `Authorization: Bearer <key>` only when a key is saved. The body is built by hand in about 20 lines and tested, since `ureq`'s multipart support is marked unversioned and pulls in two more crates. The boundary is a fresh UUID. A `verbose_json` answer gives timed segments. An answer with only `text`, as `gpt-4o-transcribe` gives, becomes one segment spanning the piece it came from.
- **Format**: OpenAI accepts flac, mp3, mp4, mpeg, mpga, m4a, ogg, wav and webm, not ADTS. Each piece is repackaged into M4A with `/usr/bin/afconvert -f m4af -d 0`, which ships with macOS and copies the AAC frames as they are, without encoding them again. The pieces are written to a folder of their own in the temp folder, which is deleted when the job ends, whether it succeeds or fails.
- **Size**: OpenAI takes files up to 25 MB. A pure `adts::chunks` cuts a track between ADTS frames into pieces of at most 20 MB, about 40 minutes at 65 kbit/s, reading each frame's header for its length, sample rate and sample count. It gives each piece's start, which offsets that piece's segments. A frame cut short at the end, as a crash leaves one, is dropped. A cut can split a word.
- **Servers**: speaches (formerly faster-whisper-server) serves the same endpoint at `/v1`. whisper.cpp's server needs `--inference-path /v1/audio/transcriptions` and `--convert` to read M4A. LM Studio does not transcribe.
- **One server config**: remote transcription uses the OpenAI-compatible server Summaries use: its address, and its key in the Keychain. The server has two Model fields, one for Summaries and one for Transcripts (`app_state.transcription_model`, `whisper-1` until changed).
- **Choices**: `app_state.transcription_provider` (`apple` or `openai`, `apple` by default) and `app_state.transcription_locale` (`NULL` follows the Mac's locale). The Language select lists SpeechAnalyzer's supported locales by name, with "System (<language>)" first. A remote Model gets the same locale's language.
- **Consent**: `remote_audio_consents` has one row per `(provider, model, host)` the user agreed to, with `acknowledged_at`. The host is lowercase, without port or credentials, read with the same `Uri` parser the HTTP client sends with, so the host judged local or asked about is the one a request goes to; an address that parser rejects is never local and gets no audio. Before an upload, `consent_needed` in `crates/ui/src/native_view/notes/consent.rs` checks for that key, unless `runs_locally` says the Model is on the Mac. Without it, an alert asks "Send this Recording to <Provider>?": Send stores the key and transcribes, and Don't send leaves the Recording untranscribed. The check runs again when the job starts, so a Model or address changed while a Note waited cannot receive audio the user did not agree to, and an older Recording queued while the server was local never goes to it once its address is remote. Stopping a Recording asks too. On quit and window close nothing can ask, so the Note waits.
- **Why the host**: a Model name says little about who runs it. `whisper-1` on `api.openai.com` and `whisper-1` on a colleague's server are different parties, so a new host asks again, as does a new Model on the same host. The port is left out: one host is one party.
- **Backfill**: older finished Recordings without a Transcript (`Notes::untranscribed`) are transcribed without asking, at launch, when a Transcription Model is picked, and when the server's address, Transcription Model or key is finished, only by a Model that `runs_locally`, the rule ADR 0007 set for Summaries. With a remote Model, the Note's Transcript tab says "Not transcribed yet" with "Transcribe with <Provider>", one Note at a time, after consent.
- **Who made it**: `notes.transcript_provider` stores the Provider's id beside `transcript_model`, and is set and cleared with it. The migration sets `apple` on existing Transcripts. Since SQLite checks a new column's `CHECK` against existing rows, `crumble-notes` keeps the two columns paired, not a constraint. The Note shows "Transcribed by Apple, on this Mac", or "Transcribed by <Provider> · <model>".
- **Per Note**: "Transcribe again with…" in the Note actions menu (or "Transcribe with…" before there is a Transcript) runs another ready Provider for that Note, asking first when it replaces a Transcript, then for consent when needed.

## Privacy

Apple's Model keeps the audio on the Mac. A remote server receives the audio of both tracks of each Recording it transcribes, and nothing else: no Memo, no Event details, no Summary. It receives them only after the user picked it, as the Transcription Model or for one Note, and agreed once for that Model on that host. Settings says "A remote server receives the Recording's audio." under the select. Picking a remote Model sends only Recordings made from then on, and older ones one at a time when the user asks. A server addressed by a loopback host, with `http://` or `https://`, counts as local and is not asked about; any other address, even one that happens to be this Mac, counts as remote. A remote Provider may keep the audio under its own terms, which Crumble cannot see or change. Removing a consent is not offered yet.

## Considered Options

- **Converting with ExtAudioFile through objc2**: no subprocess, but about a hundred lines of `unsafe` Core Audio for what `afconvert` does in one call, and it would re-encode where `afconvert -d 0` copies frames.
- **Uploading the ADTS file renamed to `.aac`**: smaller code, but the API rejects the format.
- **WAV or FLAC**: every Whisper server reads them, but they are 5 to 20 times larger, so an hour needs many more pieces.
- **Consent per Provider only**: one answer would then cover a different server or Model the user never saw named.
- **Consent per Recording**: safest, but asking after every meeting teaches people to click Send without reading.
- **Keeping consent in Settings only, as a checkbox**: easy to miss. An alert names the host and the Model at the moment audio would go.

## Consequences

- `crumble-transcribe` depends on `crumble-remote`, `serde_json` and `uuid`, and runs `afconvert`, so remote transcription works only on macOS.
- A remote Transcript's quality, cost and retention depend on the server and Model picked; each Transcript records its Provider and Model.
- `gpt-4o-transcribe` and similar Models answer only `json`. They reject `verbose_json` with an error that Crumble shows, so `whisper-1` is the default.
- A cut between pieces can split a word, every 40 minutes or so of one track.
- A changed Model or address asks again before its first upload, and a Note queued before the change waits for the user.
