# Local Models through transcribe.cpp and Handy's model list

Crumble downloads and runs its own Transcription Models, Local Models, beside Apple's SpeechAnalyzer and remote servers. ADR 0006 rejected this ("Whisper on device") because Crumble would have to ship and update its own models. That cost is now carried by others: Handy, an MIT-licensed open-source dictation app, publishes a list of about 70 speech Models as GGUF files on Hugging Face, with measured accuracy and speed, and runs them all through one MIT-licensed library, transcribe.cpp (`handy-computer/transcribe.cpp`, Rust binding `transcribe-cpp`). Crumble is open source too, so it reuses both, with attribution, and does not build its own list or runtime.

## Rules

- **The list is Handy's, copied verbatim.** `crates/local-models` holds Handy's `catalog.json` unchanged, read with `include_str!`, and `HANDY_SOURCE` beside it names the Handy release tag and commit it came from. Crumble shows every Model in it, whatever its license (Crumble is free and non-commercial), each card naming its license. Only each Model's `default_quant` is offered. Accuracy and speed bars are Handy's `accuracy_score` and `speed_score`, computed by Handy from Hugging Face model cards: WER on LibriSpeech test-clean or FLEURS, and real-time factor on one reference laptop, so speed does not reflect the user's Mac. Handy's `capabilities.streaming` is kept on every Model so live Transcripts can use it later. Apple's Model has no scores and shows "Built into macOS".
- **Syncing the list**: a weekly and on-demand GitHub workflow compares Handy's latest release tag with `HANDY_SOURCE`. On a change it copies the file and updates one standing PR on `sync/handy-catalog`, listing added, removed and changed Models and calling out every changed `revision` or `sha256`, since those decide which weights users download. It opens the PR with a fine-grained token (`CATALOG_SYNC_TOKEN`), because a PR opened with `GITHUB_TOKEN` does not trigger CI. A test deserializes the file and asserts `catalog_version == 2`, so a format change upstream fails that PR until the parser is adapted. Following release tags rather than Handy's `main` keeps out entries for models transcribe.cpp has not released support for yet.
- **Downloads**: only from Hugging Face, at the revision the list pins, never from Handy's mirror, into `~/Library/Application Support/Crumble/models/`. A download resumes with HTTP Range, checks free space first, and checks the file's `sha256` when it ends, deleting it on a mismatch. Cancel keeps the partial file for the next Download. Several downloads can run at once; quitting stops them. Beside each downloaded file Crumble writes a copy of its list entry, so a Model a later sync drops stays usable and listed as "No longer offered" until deleted. A downloaded Model is recognized by its file name, and a sync that changes its `revision` does not ask to download it again.
- **Two crates**: `crumble-local-models` manages Local Models (the list, the models folder, downloads, deletion) with no GPUI and no C++. `crumble-transcribe` transcribes: it alone depends on `transcribe-cpp`, which `scripts/check-crate-boundaries.py` enforces, and it does not know the list: `crumble-ui` hands its `Local` Transcriber the Model's file, the VAD file and the Model's name. `crumble-remote`'s `Provider` gains `local`, which `runs_locally` counts as on the Mac, so a Local Model never asks for audio consent.
- **A worker process**: ggml on Metal can crash its process, and a transcription job can run while the next meeting records. So a Local Model runs in a worker, the same `crumble` binary started with `--transcription-worker`, checked in `main` before GPUI starts, one process per job. It gets the Model's file, the VAD file, the language, `gpu` or `cpu`, and the tracks as arguments, and prints progress and `start_ms\tend_ms\ttext` lines, each with its track, on stdout, after the format of ADR 0006's Swift bridge. A worker killed by a signal is retried once on the CPU, then the job fails with "Couldn't transcribe this recording." and Try again. The worker decodes each track to 16 kHz mono f32 PCM through ExtAudioFile in `crumble-audio`, about 230 MB for an hour of one track.
- **Chunking**: Whisper and the Parakeet family take an hour of audio in one call and give their own segment or token times. The worker tells them apart by the loaded Model's architecture, length limit and timestamps. Models with a length cap or a short window (Canary, Qwen3, Cohere, Granite, Voxtral, Moonshine, SenseVoice and others) are cut at pauses into chunks of 5 to 40 s by Silero VAD, through transcribe.cpp's `VadSession`, with the chunker ported from Handy's `audio_toolkit/chunking.rs`. Each chunk keeps its start, and a Model without timestamps gives one segment per chunk, so its lines seek to the chunk's start; its card says "Rough timestamps". The VAD file, 1.2 MB, is downloaded, hidden from the list, with the first Local Model, and deleted with the last.
- **Settings**: Local Models has its own section, which downloads and deletes them and can pick a downloaded one with Use. The Transcription section's select lists Apple's Model, each downloaded Local Model and the OpenAI-compatible server. Deleting the Model in use, after a confirmation, picks Apple's Model; a picked Model whose file is gone is reported, never silently replaced.
- **When transcription runs, for every Model**: on its own only when Stop ends a Recording. Every other Transcript is asked for: per Note, with Try again, or with one Transcription section button that queues every finished Recording without a Transcript to the picked Model, after consent when it is remote. This replaces the launch and on-pick backfill of ADR 0006 and ADR 0008. Summaries keep theirs.
- **Attribution**: `THIRD_PARTY_NOTICES` carries Handy's and transcribe.cpp's MIT notices, the copied list and the ported chunker cite them, and the Local Models section says the list comes from Handy.

## Considered Options

- **A pure-Rust runtime**: `wavo` reads the same GGUF files on wgpu and Metal with no CMake, and claims to be faster than transcribe.cpp, but it was 12 days old with one maintainer and no streaming, Nemotron or Parakeet Unified. `parakeet-rs` on burn plus candle's Whisper is two stacks, the burn backend experimental and capped at about 5 minutes, with Whisper's windowing left to write. As the files are the same, `wavo` can replace transcribe.cpp later behind the worker.
- **ONNX Runtime stacks** (`sherpa-onnx`, `transcribe-rs`): a shipped C++ runtime with CoreML rather than Metal, and Whisper still through whisper.cpp.
- **Our own curated list or generator script**: picks the Models and computes the scores on Apple hardware, but leaves Crumble maintaining what Handy already maintains.
- **Searching Hugging Face live**: arbitrary repos have no scores and may not load.
- **Running Local Models in Crumble's process**: no worker, but a GPU crash would also stop a Recording in progress.
- **Keeping only Models with their own timestamps**: exact seek links everywhere, but drops Canary, Cohere and other strong Models.
- **Marking removed entries retired in our copy**: keeps metadata in one file, but the copy would no longer be Handy's, and every sync would merge.

## Consequences

- Building needs CMake and compiles ggml's C++ once per cache; the macOS runners have CMake.
- Models come from Handy's Hugging Face organization; a PR review of each sync is what decides which weights users get.
- Speed bars rank Models on Handy's reference laptop, not on the user's Mac.
- Without backfill, a Recording whose transcription was cut short by quitting waits for the user's click.
- Live Transcripts (streaming) are a later decision; they will need the worker to stay up for a whole Recording and to take audio in pieces rather than whole tracks.
