# Remote Providers as a registry, with API keys only

Crumble reaches seven companies' Models and any OpenAI-compatible server, for three jobs: Transcription, Summary, and Intelligence, the general-purpose Model Crumble's Chat talks to. ADRs 0007 and 0008 wired two remote Providers by hand, Claude and one OpenAI-compatible server, each with its own `app_state` columns, Settings group, Keychain account and Summarizer or Transcriber type. Adding more that way copies that wiring per Provider and per job. Instead `crumble-remote` keeps one `Remote` descriptor per Provider, a static value that says where its API is, what its keys look like, which jobs it does through which API, the Models it suggests, and how to check a key without spending tokens. Settings, `crumble-summarize` and `crumble-transcribe` read descriptors, so a Provider whose APIs Crumble already speaks is a `Provider` variant, one file, a logo and its tests. Every Provider takes an API key; no subscription sign-in is offered yet. This supersedes, in ADR 0007, the Keychain service and accounts, the Provider ids, the Model columns, the `Claude` and `OpenAiCompatible` Summarizers and the Test; and, in ADR 0008, the Provider ids, the `OpenAiCompatible` Transcriber and "One server config". The rest of both stands.

## Rules

- **The seam**: beside `Apple` and `Local`, `Provider` holds `Anthropic` (formerly `Claude`), `OpenAi`, `Gemini`, `ElevenLabs`, `OpenRouter`, `DeepSeek`, `Xai` and `OpenAiCompatible`. Each has an `id`, a `name` and a `remote()` arm returning its `&'static Remote`, defined in `crates/remote/src/remote/<id>.rs`. `Provider::ALL` lists every Provider, `Provider::REMOTE` the remote ones in Settings' order. Its logo is `assets/lobehub/<id>.svg`, which the UI maps in `crates/ui/src/assets.rs` and draws mono or in color by an exhaustive `match`; the server has none. `Chat` names the three chat APIs Crumble speaks (Anthropic's Messages, OpenAI's chat completions, Gemini's `generateContent`) and `Speech` the four transcription APIs (OpenAI's audio transcriptions, ElevenLabs' and xAI's speech to text, Gemini's Interactions). One `Remote` Summarizer and one `Remote` Transcriber, each `{ provider, base_url, api_key, model }`, replace `Claude` and both `OpenAiCompatible` types and dispatch on that API; a wire adapter is added only for an API they do not speak yet. [Adding a Provider](../architecture/adding-a-provider.md) has the checklist.
- **Jobs**: `Job` is `Transcription`, `Summary` or `Intelligence`. A remote Provider transcribes when it has a `Speech` API and does the other two when it has a `Chat` API; Apple's Models do all three, Local Models only Transcription. Four declarations follow from the descriptor, and a test pins them:

  | Provider | id | Subscription only | Chats | Transcribes | Streams |
  | --- | --- | --- | --- | --- | --- |
  | Anthropic | `anthropic` | no | yes | no | yes |
  | OpenAI | `openai` | no | yes | yes | yes |
  | Google Gemini | `gemini` | no | yes | yes | yes |
  | ElevenLabs | `elevenlabs` | no | no | yes | no |
  | OpenRouter | `openrouter` | no | yes | yes | yes |

  | xAI | `xai` | no | yes | yes | yes |
  | OpenAI-compatible server | `openai-compatible` | no | yes | yes | yes |

  A Provider that chats makes Summaries and answers Intelligence; Settings › Providers names these "Intelligence" and "Transcription".
- **API keys only**: a descriptor's `SignIn` holds `api_key: Option<KeyFormat>` and `subscription: Option<Subscription>`. `Subscription` is an empty enum, so nothing builds one and no Provider is subscription only. It is the seam for a subscription sign-in through OAuth, one variant per flow, added once that Provider allows the flow to apps like Crumble. None did in V1:
  - Anthropic: "Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, or Max plan credentials on behalf of their users" ([legal and compliance](https://code.claude.com/docs/en/legal-and-compliance), read 2026-10-22). Spoofed Claude Code sign-ins are blocked on its servers since 2026-01-09. Max and Team plans include monthly API credits since 2026-10-07 ([support](https://support.claude.com/en/articles/17154008-monthly-api-credits-for-max-and-team-plans)), which pay for a normal API key.
  - Google: Gemini CLI's terms call reaching its services with its OAuth from third-party software "a violation of applicable terms and policies" ([tos-privacy.md](https://github.com/google-gemini/gemini-cli/blob/main/docs/resources/tos-privacy.md)), as do [Antigravity's terms](https://antigravity.google/terms), §6. Google suspended accounts for it in February and September 2026, and bans one for good at its second offence. Google AI plan benefits do not cover API keys ([plans](https://ai.google.dev/gemini-api/docs/google-ai-plans)).
  - xAI signs in SuperGrok only through the Grok CLI's own client, for partners, with no public registration. GitHub Copilot's API is undocumented for third parties and partner-only.
  - Candidates for later: OpenAI's "Sign in with ChatGPT" (DevDay, 2026-09-29), open to open-source and locally hosted apps ([docs](https://developers.openai.com/siwc/token-sharing-open-source)), but only for the Responses API, streamed, with no audio: Summaries and Intelligence, never Transcription. OpenRouter's PKCE flow (`https://openrouter.ai/auth`, then `POST /api/v1/auth/keys`) is meant for third-party apps and ends in an ordinary API key.
- **Key format**: `KeyFormat` holds a pattern, the ways keys start, refused kinds, whether a key is required, and its header. Settings checks a pasted key before any request: empty, valid, or invalid with why, such as "These keys start with sk-ant-api." or "This key looks incomplete. Paste it again." Each pattern is a permissive form of the shape secret scanners (gitleaks, TruffleHog, GitHub secret scanning) match, so a later key version with the same prefix still passes; the `regex` crate has no lookahead, so refused kinds are checked first.

  | Provider | Pattern | Refused | Header |
  | --- | --- | --- | --- |
  | Anthropic | `^sk-ant-api\d{2}-[A-Za-z0-9_-]{40,}$` | Admin keys (`sk-ant-admin01-`), Claude subscription tokens (`sk-ant-oat01-`, `sk-ant-ort01-`) | `x-api-key`, with `anthropic-version: 2023-06-01` |
  | OpenAI | `^sk-(?:(?:proj\|svcacct\|None)-)?[A-Za-z0-9_-]{40,}$` | Admin keys (`sk-admin-`), Anthropic, OpenRouter and DeepSeek keys | Bearer |
  | Google Gemini | `^(?:AIza[0-9A-Za-z_-]{35}\|AQ\.[0-9A-Za-z_.-]{20,})$` | | `x-goog-api-key` |
  | ElevenLabs | `^(?:sk_[0-9a-f]{48}\|[0-9a-f]{32})$` | | `xi-api-key` |
  | OpenRouter | `^sk-or-v1-[0-9a-f]{64}$` | | Bearer, with `http-referer` and `x-openrouter-title` naming Crumble |
  | DeepSeek | `^sk-[0-9a-f]{32}$` | Anthropic, OpenRouter and OpenAI keys | Bearer |
  | xAI | `^xai-[A-Za-z0-9_-]{40,}$` | | Bearer |
  | OpenAI-compatible server | any, optional | | Bearer, only when a key is saved |

- **The ping**: `crumble_remote::ping(provider, base_url, key)` proves a key and lists Models without spending tokens: it only GETs a key's details or a Models list, within 20 s. Anthropic: `/v1/models?limit=1000`. OpenAI, DeepSeek and the server: `{base}/models`. Gemini: `/v1beta/models?pageSize=1000`. ElevenLabs: `/v1/user`, as its list holds only voice Models; Scribe's are suggested. OpenRouter: `/api/v1/key`, then its public `/api/v1/models` without the key. xAI: `/v1/api-key`, whose answer also says whether the key or its team is blocked, then `/v1/models`, chat Models only. A 400 or 401 refuses the key; a 403 is a key that may not list Models, which passes with its Models typed in, except at Gemini, whose keys have no scopes, where a 403 refuses the key with Google's reason; a 404 is an address with nothing behind it. An Anthropic key made for more than one workspace is refused with a sentence saying so, as its requests would need an `anthropic-workspace-id` header Crumble doesn't send. No request follows a redirect, as a key in a header of its own would go along to wherever it points, so a 3xx is an address problem. A passed ping does not prove the account has credit; that shows on its first job. It replaces ADR 0007's Test, which spent tokens on a tiny prompt. A Provider's dialog pings when a key that looks right is typed or pasted, when an address is finished, and on Check again. The Transcription, Summary and Intelligence sections ping a set-up Provider picked in them once a run, in the background with the saved key, to list its Models, and again after a failure once Settings shows a section again or the key or address changes. A passed ping, like a saved key or a picked Summary Model, starts the Summary backfill. Each list is split into chat and speech Models by the Provider's own fields, or by id where it has none (OpenAI, xAI); a server's ids say nothing of the job, so each is offered for both.
- **Keychain**: keys move to a new service, `io.github.mastro993.crumble.api-keys`, account the Provider's id. `secrets::saved()` lists its accounts from item attributes without loading a key, so launch reads none; `get` runs only when a check or job starts. `secrets::move_old_keys()`, at every launch before `saved()`, moves `claude` to `anthropic` and `openai` to `openai-compatible` from the old service `io.github.mastro993.crumble`, never over a key already saved, then deletes the old items. The service is new because the old `openai` account held the OpenAI-compatible server's key, not OpenAI's: under one service the same account would name two Providers' keys depending on the build reading it. Keys are write-only: Settings never shows one again.
- **Ids and storage** (migration 000011): `claude` becomes `anthropic` and `openai` becomes `openai-compatible` in `app_state.summary_provider`, `app_state.transcription_provider`, `notes.transcript_provider`, `notes.summary_provider` and `remote_audio_consents.provider`. A consent keeps its Model and host, as the same party gets the audio. The three columns that listed ids in a `CHECK` are rebuilt without one, so a new Provider needs no migration; `Provider::from_id` is the list. A new `providers` table holds one row per remote Provider the user changed: `id`, `base_url`, `summary_model`, `transcription_model` and `intelligence_model`, each `NULL` for the Provider's default, the row deleted once all are `NULL` again. Claude's Model and the server's address and Models move into it, and `app_state` drops `claude_model`, `openai_base_url`, `openai_model` and `transcription_model` and gains `intelligence_provider`. `Store::provider(id)` and `Store::set_provider(id, settings)` read and write a whole row.
- **Address**: every remote Provider's address can be replaced, such as ElevenLabs' EU, India and Singapore hosts or a proxy. Requests go to the saved address, else the Provider's usual one; the server has none and must be given one. `runs_locally(provider, base_url)` still counts only the OpenAI-compatible server at a loopback address as on the Mac, now told apart as the one Provider with no usual address. A company's Models never run on the Mac, so its API counts as remote even through a proxy at `http://127.0.0.1:4000`, which passes what it reads on to the company: it gets no backfill and asks for consent before audio.
- **Models per job**: a job uses the Model saved for it, else the descriptor's default. A Provider's dialog sets up only its key and address; each job's section in Settings picks a Provider, then that Provider's Model for the job, saved per Provider, so switching back to one finds its Model again. The Model select offers Crumble's suggestions first, then those the ping listed, then the saved Model; any other, such as a new Model or one on a server whose list fails, is typed into the select's search field and saved like a listed one. A remote Provider is set up when it has a key if it requires one and an address requests can go to, which puts it in the job sections' Provider selects, and ready for a job when it also does the job and has a Model.

- **Chat APIs**: Anthropic's Messages API keeps ADR 0007's request. OpenAI's chat completions serve OpenAI, OpenRouter, DeepSeek, xAI and the server, with no token cap; only the message's `content` is kept, so DeepSeek's `reasoning_content` is not. Gemini gets `POST /v1beta/models/{model}:generateContent` with a `systemInstruction`, its `thought` parts skipped. A refused or blocked answer and one cut short are errors, as before.
- **Transcription APIs**: each track still goes up on its own in M4A pieces (ADR 0008), under 20 MB, or 10 MB for Gemini, and cut by length too where a Model caps it, as a track's size says little of its length.
  - OpenAI's audio transcriptions (OpenAI, OpenRouter, the server) ask each Model for what it gives: Whisper Models `verbose_json` with segment times, `diarize` Models `diarized_json` with `chunking_strategy=auto`, and every other, such as `gpt-transcribe`, `json`, text alone, which becomes one segment spanning its piece. A `diarize` Model gets pieces of at most 20 minutes, under its 1,400 s limit, and a text-only one pieces of at most 5 minutes, as its answer stops at 2,000 tokens. The server gets Whisper's request unless the id says `transcribe`. `whisper-1` is OpenAI's default as the one that times segments, but OpenAI shuts it down, with the `gpt-4o` transcribe Models, on 2027-02-26.
  - ElevenLabs' `POST /v1/speech-to-text` (`timestamps_granularity=word`, `tag_audio_events=false`) and xAI's `POST /v1/stt` (the file last) answer with timed words.
  - Gemini: each piece goes up through the Files API's resumable upload, its upload address moved onto the user's base URL, its path included, so the key goes nowhere else, waits until Google has processed it (3 minutes at most), is transcribed by `POST /v1beta/interactions` with a verbatim `transcription_config`, word times, the language and `store: false`, and is deleted afterwards whatever happened. Word times hold for 30 minutes of audio, hence the smaller pieces, of at most 10 MB and 25 minutes.
  - Timed words become segments: a pause of 800 ms or more starts one, a sentence's end closes one that has run 2 s, and none runs past 30 s. Words join with single spaces, none before punctuation or between Chinese or Japanese words. An answer without words becomes one segment spanning its piece.
  - The language goes as an ISO 639-1 code, a BCP-47 tag for Gemini, and not at all for Detect automatically.
- **Intelligence**: `app_state.intelligence_provider` keeps the Provider picked in Settings › Intelligence for the Chat page, `NULL` until one is, with no fallback to Apple's; each remote Provider's Intelligence Model is its `providers.intelligence_model`. The Chat page does not use it yet.
- **Streaming**: `streams` records whether a Provider's chat API can stream an answer, which Intelligence will need. Summaries still do not stream (ADR 0007).

## Privacy

What each job sends is unchanged: a Summary Model gets a Transcript's text, a Transcription Model a Recording's audio after consent for that Model on that host (ADR 0008), and an Intelligence Model what the user asks in Chat. Each Provider's dialog in Settings says which it gets. Consent names the host of that Provider's own address, so a replaced address asks again. Only the OpenAI-compatible server at a loopback address counts as on the Mac; a company's API counts as remote at any address, a proxy on the Mac included, and any other address counts as remote. Keys are read from the Keychain only when a check or job starts, go only into their request's header, and never into SQLite, logs, errors or the UI; a Provider's message that repeats one has it taken out, and no request follows a redirect to another host. Requests to OpenRouter name Crumble, which shows in the user's OpenRouter activity. Gemini interactions ask Google not to store them, and each uploaded piece is deleted after its interaction. A Provider may keep what it receives under its own terms.

## Considered Options

- **A Summarizer and Transcriber per Provider**: each would repeat the HTTP and error handling of Providers that speak the same API; five of the eight speak OpenAI's chat completions.
- **A data file of Providers**, such as models.dev's: no build for a new Provider, but key patterns, pings and list parsers are code, and an unreviewed file would decide where keys go.
- **OpenAI-compatible routes for every Provider**: Anthropic's is for testing, not production, and strips audio; Gemini's answers audio transcriptions with 404.
- **A subscription sign-in in V1**: only OpenAI's is allowed; it needs token refresh, a registered host id, OpenAI's branded button and usage screens, and covers no Transcription.
- **One Keychain service, accounts renamed in place**: until the move ran, and in any older build, `openai` would name two Providers' keys.
- **Any Provider at a loopback address counting as on the Mac**: one rule for every address, but a proxy there passes a company's requests on to the company, so a Recording's audio would leave the Mac with no consent asked and older Transcripts would go to it unasked.
- **Keeping the `CHECK` constraints**: each new Provider would need a migration that rebuilds three columns.
- **Wispr Flow**: its API is open only to organizations its team approves, edits dictation rather than transcribing verbatim, gives no times, and takes at most 6 minutes of WAV per request; its terms forbid other interfaces to a subscription. Left out.
- **GitHub Copilot**: no pay-per-token keys, only a subscription; its API is undocumented and partner-only, and the supported route runs the Copilot CLI's runtime. It would be subscription only and chat only. Left out.

## Consequences

- A Provider whose APIs Crumble speaks needs a `Provider` variant, a descriptor, a logo with its entry in the UI's assets and its arm in the UI's logo `match`, and tests. Its id never changes once released: Notes, choices, consents and its Keychain item keep it.
- Errors and "Summarized by" say "Anthropic", not "Claude", and the server is "OpenAI-compatible server".
- A key that passes the ping can still fail its first job for lack of credit, with the Provider's error.
- Suggested Models go stale between releases; the listed and typed ones cover the gap, and a saved Model no longer listed stays picked.
- OpenAI's Transcripts are timed per piece once `whisper-1` shuts down on 2027-02-26, unless a Model with times replaces it.
- Reverting migration 000011 maps the old ids back; a Provider the old app lacks falls back to Apple's.
- A subscription sign-in later is a `Subscription` variant, its tokens in the Keychain beside the keys, and a sign-in button in the Provider's dialog ([Adding a Provider](../architecture/adding-a-provider.md#adding-a-subscription-sign-in)).
