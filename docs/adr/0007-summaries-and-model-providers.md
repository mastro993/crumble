# Summaries from a Model the user picks, with keys in the Keychain

A Note's Summary is made from its Transcript only, never from the Memo, and a new Transcript makes a new one. The user picks the Model that makes it in Settings, from three Providers: Apple's on-device Foundation Models (macOS 26, with Apple Intelligence on), which keeps everything on the Mac; the Claude API; and any server that speaks OpenAI's chat completions, which covers Ollama and LM Studio on the same Mac as well as hosted services. Each is one implementation of a `Summarizer` trait in `crumble-summarize`, the one trait with several real implementations that this layer of the Notes stack adds. Transcription gets its own trait when its second implementation lands.

## Rules

- **The trait**: `Summarizer::summarize(&self, transcript, progress) -> anyhow::Result<String>` blocks, so callers run it off the main thread, and returns Markdown. `provider()` and `model()` say what made it. Its error is a sentence a user can act on. The three implementations are `Apple`, `Claude { api_key, model }` and `OpenAiCompatible { base_url, api_key, model }`. The UI builds one from the Settings picks and the Keychain each time a job starts.
- **The text a Model reads**: `transcript_text` writes one `You: …` or `Others: …` line per segment, in order, with the line's whitespace collapsed. "You" is the microphone track and "Others" the Mac's sound (ADR 0006).
- **The prompt**: the instructions explain the "You"/"Others" labels and warn that speech recognition mishears words. They ask for Markdown in the language the meeting was held in: a short overview paragraph, then "Key points", "Decisions" and "Action items" (with owners when the meeting named them), with the section titles in that language and "None." under an empty section. They forbid inventing names, numbers, dates, decisions or tasks, and turning a suggestion into a decision, and they ask for no preamble. anarlog, the open-source meeting-notes app ADR 0005 mentions, writes the same kind of speaker-labelled lines, keeps its own anti-invention rule, and lets the model choose its sections. Crumble fixes the sections so every Summary reads the same.
- **Apple's bridge**: `crates/summarize/swift/Summarize.swift` is built as ADR 0006 describes for `crumble-transcribe`: `xcrun swiftc -emit-library -static` from `build.rs`, Swift 5 mode, linked with Foundation and FoundationModels, with every `unsafe` call in `src/ffi.rs`. Its C functions are `crumble_summarize_availability`, `crumble_summarize_context_size`, `crumble_summarize_token_counts(texts, out)` (texts separated by U+001E, one count per line back), `crumble_summarize_respond(instructions, prompt, max_tokens, out)` and `crumble_summarize_free`. Each async call blocks a Rust background thread on a semaphore. The model is `SystemLanguageModel(useCase: .general, guardrails: .permissiveContentTransformations)`, since summarizing rewrites text the user supplied. Its errors become sentences in Swift, such as "The Transcript was too long for Apple's on-device model."
- **Chunking for Apple's context**: the model reads about 4,096 tokens at once, its instructions, prompt and answer together. `SystemLanguageModel.tokenCount(for:)` (macOS 26.4) counts each line; before 26.4 the bridge estimates one token per three UTF-8 bytes. The budget is the context size minus the longest instructions, 1,000 tokens for the answer, and a 100-token margin. A pure `chunks(costs, budget)` groups the lines, in order, into runs that fit. When there is one run, the model writes the Summary. Otherwise it takes notes on each run, those notes become the lines of the next round, and so on until they fit, for at most four rounds. Progress counts answers given, and only moves forward.
- **Remote Providers**: Claude gets `POST https://api.anthropic.com/v1/messages` with `x-api-key`, `anthropic-version: 2023-06-01`, `system` set to the instructions, and `max_tokens` 16,000, room for a Summary and any thinking the Model does first. The default Model id is `claude-sonnet-5-5`, editable in Settings. An OpenAI-compatible server gets `POST {base_url}/chat/completions` with a system and a user message, and `Authorization: Bearer <key>` only when a key is saved, but no token cap: servers name that parameter differently (`max_tokens`, `max_completion_tokens`), and some refuse the other name. A Summary cut short (`stop_reason` `max_tokens`, `finish_reason` `length`) is an error, never kept as finished. A Test passes on any answer, so a Model that thinks before it speaks passes too. Each gets the whole Transcript in one request after one check that it is under 600,000 characters, about 150,000 tokens. Neither streams.
- **The HTTP client** is `ureq` 3 with rustls and its `json` feature: blocking, as the jobs already run on a background thread, and small. `rustls` and `ring` were already in the build through `gpui-kit`'s assets crate. Bodies are built and parsed with `serde_json::Value`, so no crate takes `serde` derives. Requests time out after 10 minutes, as a local Model can take minutes on an hour of speech. Every status reaches the parser (`http_status_as_error(false)`), so failures map to sentences: 401 "didn't accept the API key", 403 not allowed to use the Model, 404 "has no Model named …", 429 too many requests, 5xx a problem on their side, another 4xx the server's own message, and no response "Couldn't reach …", with any user name and password taken out of the address.
- **Keys in the Keychain**: `crumble_store::secrets` keeps one generic password per Provider: service `io.github.mastro993.crumble`, account the Provider's id (`claude`, `openai`). Its API is `get`, `set` and `delete` by that id, through the `security-framework` crate. The items go in the login Keychain, whose access list trusts the app that made them; with a stable signing identity (README), later builds read them without a prompt, while an ad-hoc signed build may be asked for the login password. A key is never stored in SQLite, logged, put in an error, or shown again: Settings shows "Saved in Keychain" and Remove. `secrets` lives in `crumble-store`, beside the other choices kept across restarts, as a separate crate for three functions would hide no state of its own.
- **Choices**: `crumble-store` keeps them as Provider ids, so it does not depend on `crumble-summarize`. `app_state` gains `summary_provider` (`apple`, `claude`, `openai`, or `NULL` until one is picked), `claude_model`, `openai_base_url` and `openai_model`. With nothing picked, the Summary Model is Apple's when it can run, else none.
- **Storage**: `notes` gains `summary` (Markdown), `summary_provider`, `summary_model` and `summarized_at`, all set or all `NULL`. `Notes::set_summary` needs a Transcript. A new Transcript clears all four in the same transaction that replaces it, so a Summary never sits beside a Transcript it was not made from, and so do deleting the Recording and soft-deleting the Note. `notes` now has more than 16 columns, so Diesel's `32-column-tables` feature is on.
- **When it runs**: a new Transcript, stored after Stop, after a Recording is recovered at launch, or after Transcribe again, is summarized at once by the Summary Model, whichever it is. Older Transcripts without a Summary (`Notes::unsummarized`) are backfilled without asking, at launch and when a Summary Model is picked, only by a Model that runs locally and has what it needs: Apple's when it can run, or an OpenAI-compatible server whose host is `localhost`, `127.0.0.1` or `::1`, which the pure `runs_locally` decides. Each is queued with that Provider, so a remote one picked while they wait never gets them. With Claude or a server elsewhere, such a Note's Summary tab says "Not summarized yet" with a "Summarize with <Provider>" button for that Note alone; there is no bulk action, so picking a remote Model never sends a backlog of Transcripts. "Summarize again with…" in the Note actions menu runs it with another configured Provider: the Note's own pick over Settings', recorded in its `summary_provider` and `summary_model`. One job runs at a time on GPUI's background executor, as for Transcripts.

## Privacy

Apple's Model keeps the Transcript on the Mac. Claude and an OpenAI-compatible server receive the Transcript's text, and only that: no audio, no Memo, no Event details. They receive it only once the user has picked them, as the Summary Model or for one Note, and Settings says so under the Summary Model select. Picking one sends only the Transcripts made from then on, and older ones one at a time when the user asks. A server addressed by a loopback host, such as Ollama at `localhost:11434`, counts as local; any other address, even one that happens to be this Mac, counts as remote.

## Considered Options

- **One Model, Apple's only**: nothing would leave the Mac, but it needs Apple Intelligence on supported hardware, and its 4k context makes long meetings lossy.
- **`reqwest`**: already compiled for `gpui-kit`'s assets, but async: it would need a Tokio runtime or a blocking feature, which is more than three POSTs from a background thread need.
- **The `keyring` crate**: cross-platform, but Crumble runs only on macOS, and `security-framework` was already in the build.
- **Keys in SQLite, encrypted**: the key to decrypt them would itself need a home, which is the Keychain.
- **Streaming**: would show the Summary as it is written, but adds an SSE parser per Provider; a Summary takes seconds, so a progress bar does.
- **Summarizing in parts for every Provider**: costs quality and more requests where the context holds the whole Transcript.

## Consequences

- `crumble-summarize` uses `unsafe` for its FFI calls, so it sets `unsafe_code = "deny"`, with a `SAFETY` comment on each block, like `crumble-transcribe`.
- Apple's Model is offered only when it can run; Settings shows why otherwise ("Turn on Apple Intelligence in System Settings."). It can be turned on while Crumble runs, and Settings follows.
- A long meeting summarized by Apple's Model is a summary of notes, so details can drop out.
- Remote Summaries cost the user tokens, and their quality depends on the Model picked. Each Summary records the Provider and Model that made it.
- A new Transcript is summarized with the Summary Model picked in Settings, not with the Provider the Note picked last.
