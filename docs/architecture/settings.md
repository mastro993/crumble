# Settings

Part of the [native architecture](native.md): the Settings page.

## Layout

- A sidebar at the panel's leading edge is titled Settings, in 18 pt bold level with the section's title, and lists the sections in two groups, each under a muted 14 pt label: Calendar holds General and Calendars, and Notes holds Recording, Transcription, Local Models, Summary, and Providers. Each section is a 30 pt row with a 16 pt icon and a 10 pt corner radius, all in the selected row's ink so only the fill marks the section on screen; 12 pt separate a group from the one before it. It sits on the Agenda list's surface with a hairline on its trailing edge. It resizes like the Agenda list and shares its width (see Shell in [native](native.md)), but never collapses: the sidebar toggle and `Cmd-B` do nothing on this page.
- Clicking a row, or Enter or Space on a focused one, shows that section beside the column, under its title, at most 720 pt wide and centered in the space beside the sidebar; the content scrolls on its own. Settings opens on General, and the rail's Settings button returns to the section picked last while Crumble runs; an Open Settings link elsewhere opens the section it names. Opening Settings or picking a section reads the models folder again, so a Local Model deleted in Finder drops out of the lists. Picking a section is not recorded for Back.

## Settings

- `crates/store` keeps the choices made in Settings, with the rest of the state Crumble keeps across restarts, in the SQLite database `crumble.sqlite3` in the platform data directory (`~/Library/Application Support/Crumble` on macOS), creating the folder when missing. `crates/db` opens the file and runs pending migrations; `crates/store` then reads its tables into memory; views read from memory, and each change is written in its own transaction on the main thread. If the database cannot be opened, migrated, or read, the error is logged and the app runs on the defaults in an in-memory database for that run, leaving the file alone. A stored value that no longer decodes falls back to its default. If a write fails, the error is logged and the app keeps the new value in memory. `settings.json`, used before the database, is no longer read: preferences saved there reset once.
- The tables are `app_state` (one row: `first_day_of_week`, 0 for Monday, `calendar_view`, the Model choices below, and `suggest_recording`), `remote_audio_consents` (see Transcript), `accounts` (by EventKit identifier: `position` in the user's order, `color` as a palette name or `#rrggbb`, `alias`, `disabled`, `hidden`), and `calendars` (by EventKit identifier: `disabled`). An Account or Calendar row is written the first time the user changes it and kept after its values return to the defaults.
- **General** holds **First day of week**, which can be any weekday and defaults to Monday. It sets the column order of every Calendar view and where each week Period begins.
- **Calendars** lists every Account with an Alias field and a switch, and under it its Calendars, each with a checkbox, its macOS color, and its name. Settings is the only place to Disable or Enable an Account or a Calendar. An Account with an Alias is titled with it, followed by its own name in brackets. Each keystroke in the field saves the Alias. A blank Alias, or one equal to the Account's own name, is removed, so the Calendars section's Rename and the field agree. Aliases are saved in `accounts.alias`. Every Account and Calendar starts enabled; turning an Account's switch off or unchecking a Calendar Disables it. A Disabled Account greys its Calendars out and keeps their checkboxes as they were. While access is not granted the section says to connect calendars from the Calendars button in the rail, and with no Accounts it says to add them in System Settings › Internet Accounts. Disabled Accounts and Calendars are saved by EventKit identifier in `accounts.disabled` and `calendars.disabled`, and change nothing in macOS.
- **Transcription**, **Local Models**, **Summary** and **Providers** ([ADR 0007](../adr/0007-summaries-and-model-providers.md), [ADR 0008](../adr/0008-remote-transcription-and-audio-consent.md), [ADR 0010](../adr/0010-local-models-through-transcribe-cpp-and-handys-list.md)). Picking a Model or a Language transcribes nothing on its own: only Stop does (see Transcript).
  - **Transcription Model** is a select of "Apple, on this Mac", each downloaded Local Model by name, and "OpenAI-compatible server", Apple's until another is picked. Under it: "Local Models keep the audio on this Mac. A remote server receives the Recording's audio." and a Get more Models link, which opens Local Models. Picking one saves its Provider's id in `app_state.transcription_provider`, `local` for a Local Model, whose slug goes in `app_state.local_model`.
  - **Language** is a searchable select of the picked Model's languages: for a Local Model, "System (<language>)", "Detect automatically" when the Model can tell the language itself, then its languages by name; for Apple's Model and the server, "System (<language>)" then every locale SpeechAnalyzer transcribes, by name. It is saved in `app_state.transcription_locale`, `NULL` for System and `auto` for Detect automatically. A Local Model reads only a locale's language, so `it_IT` picks Italian. A saved locale the picked Model does not list stays, as an extra row, and its Transcripts fail saying so. Picking one forgets the Transcripts that failed, so they can be tried again.
  - Under them, "12 Recordings have no Transcript." with **Transcribe all**, which queues every finished Recording without a Transcript, not already waiting, to the Transcription Model; a remote one asks once, "Send 12 Recordings to <Provider>?", before any is sent. It is disabled while there is none, or the Model lacks what it needs.
  - **Local Models** lists the Models in Handy's list, under a search field that matches words of the name, a streaming toggle that keeps only Models that can stream, and a searchable language select, "All languages" first. Downloaded comes first, with Apple's built-in Model at its top ("Built into macOS", no scores, never deleted), then the downloaded Local Models; then Available to download, Handy's recommended Models first. Each card shows the name, a badge ("In use", "Recommended", or "No longer offered" for one a sync dropped), the description, Accuracy and Speed bars from Handy's scores, its languages ("English only", "99 languages"), Streaming, Rough timestamps for a Model without times of its own, its license, and its size. An Available card has Download with the size; while it downloads, a progress bar, the percentage and Cancel, which keeps what arrived for the next Download; a failed download shows why beside Download. A downloaded card shows its size, Use unless it is in use, and Delete, which asks first and, for the Model in use, picks Apple's. Use makes it the Transcription Model. Several downloads can run at once and keep going when Settings closes. Under the list: "Model list and scores from Handy · Speed measured on Handy's reference laptop.", linking Handy.
  - **Summary Model** is a select of "Apple, on this Mac", "Claude" and "OpenAI-compatible server". Apple's row is disabled while its Model cannot run, and a line under the select says why, such as "Turn on Apple Intelligence in System Settings."; the select follows when that changes while Crumble runs, and when Apple's Model becomes able to run its failures are forgotten and the backfill starts. Crumble notices only while Settings shows, whichever section is on screen. Under it: "Claude and remote servers receive the Transcript's text." Until one is picked it shows Apple's when that can run, else "Choose a Model". Picking one saves its id in `app_state.summary_provider`, and, when it runs locally (see Summary), summarizes every Note whose Transcript has speech but no Summary.
  - **Providers** holds the rest. **Claude**: API key and Model (`claude-sonnet-5-5` to start). **OpenAI-compatible server**: Address (placeholder `http://localhost:11434/v1`), an optional API key, a Summary Model, and a Transcription Model (`whisper-1` to start). The one server and key serve both jobs. Each keystroke in an Address or Model field saves it in `app_state` (`claude_model`, `openai_base_url`, `openai_model`, `transcription_model`), trimmed, and, except for the Transcription Model, clears that Provider's Test result. An Address without `http://` or `https://` fails before sending anything, and does not count as local.
  - An API key field is masked. Save or Enter moves the key into the Keychain and empties the field; from then on the row says "Saved in Keychain" with Remove. Which Providers have a key is read from the Keychain once at launch.
  - Test, one per remote Provider, sends a tiny prompt with what Settings holds and shows "Testing…", then OK for any answer, or the error. A Claude Test with no key fails before sending anything.
- **Recording** holds a "Suggest recording when a meeting starts" switch, on until turned off, saved in `app_state.suggest_recording` (see Suggestions). While it is on and macOS keeps Crumble's notifications off, a line under it says "Notifications are off for Crumble in System Settings." with Open System Settings, which opens the Notifications pane on Crumble. Crumble reads the permission at launch, each time its window becomes active, and after each Suggestion.
