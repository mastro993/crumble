# Recording and Suggestions

Part of the [native architecture](native.md): Recordings and the Suggestions that offer them.

## Recording

Recording is defined in [CONTEXT.md](../../CONTEXT.md); the design is [ADR 0005](../adr/0005-recording-with-a-process-tap.md).

- A Recording is two files in `~/Library/Application Support/Crumble/recordings/<note id>/`: `mic.aac`, the default input device, and `system.aac`, a process tap of every process's output except Crumble's. Each is mono AAC-LC in ADTS at the device's own sample rate, usually 48 kHz, at the encoder's default bit rate: about 65 kbps for speech, so about 30 MB per track and 60 MB per hour of Recording, and far less for silence. ADTS stays playable up to the last packet written when the app dies. `crates/notes` names the folder from the Note id and deletes it; `crates/audio` names and writes the files in it.
- The card header's trailing side shows, by state:
  - No Recording: Record, with a microphone icon. The first time, it asks macOS for the microphone, then starts whatever the answer: a denied microphone still records the Mac's sound. While another Note records, Record is disabled and its tooltip names that Note.
  - Recording: a red dot, the elapsed time, redrawn each second, and Stop.
  - Recorded: play or pause, a scrubber, and `position / length`. Playing past the end starts again from the beginning.
- Starting stores `recording_started_at` and stopping stores the length, the longest track's frame count. A length that fails to save is handled as a failed Memo save: the Recording shows as finished, "Couldn't save" shows, and the length is written again with every later save; a restart reads it from the files instead. A Quick note's row moves to the Recording's start. A track that cannot open or start is left out, and the Recording fails only when neither starts. A Recording that cannot start is forgotten and the card says "Couldn't record". A track whose encoder fails stops taking audio, so its file holds what came before the failure; stopping then keeps what the files hold and says "Couldn't record" too. The line shows only under the Note it is about, and goes once that Note's next start, stop or delete succeeds.
- One Recording runs at a time in the app, and it keeps running while other pages show. Quitting or closing the window stops it like Stop does; when closing asks first, only once the window closes. Stop and launch recovery keep a Recording through `Notes::finish_recording`, which stores its length, or deletes it when it holds no audio. At launch, `Notes::recover_recordings` does so for each Recording a crash left running, with the length its files hold; one that fails does not stop the others. Stopping before any audio arrived deletes the Recording the same way, with no error shown. A Recording whose files exist but cannot be read is never deleted for it: it stays unfinished, and the next launch reads it again.
- A recorded track that has heard only digital silence (every sample under 1e-6) for the first 10 s shows a line under the card with an Open System Settings button: for the Mac's sound, the Screen & System Audio Recording pane (`Privacy_ScreenCapture`), since a tap without permission hears silence; for the microphone, the Microphone pane. Once a track hears sound, its line goes.
- The IO procs copy each Core Audio cycle into 1024-frame blocks, stamped with the cycle's host time, and send them over a bounded channel to a writer thread, which drains the system track in full first, as it is the microphone's reference, then encodes up to 16 microphone blocks; a full channel drops the block and the drop count is logged at stop.
- With both tracks, `mic.aac` has the Mac's sound removed, as on speakers the microphone hears the call too. Before encoding, the writer runs WebRTC's echo canceller (AEC3, from `sonora`) on the microphone, with the system track as the reference, paired 10 ms at a time by host time. Below 8 kHz only AEC3's linear filter runs, which subtracts the echo it predicts, so the voice is never muted there, even while the call talks over it; above 8 kHz AEC3's suppressor still mutes the voice's highs while the call talks. A faint copy of the call can stay. There is no noise suppression and no gain control. The microphone waits at most 500 ms for its reference, then is cleaned against silence; the canceller's filters leave it about 9 ms later than recorded. It is always on, headphones or not. Crumble's own playback is not in the reference, so playing a Recording on speakers while another records stays in the mic track. Starting the devices happens on the main thread.
- Playback runs both files through one `AVAudioEngine`, a player node each, scheduled from the same position and started at the same host time. The player is opened when a Note with a finished Recording shows, and dropped when another row or page shows.

## Suggestions

A Suggestion is defined in [CONTEXT.md](../../CONTEXT.md); the design is [ADR 0009](../adr/0009-suggestions-through-user-notifications.md).

- While Crumble runs and the Settings switch is on, a meeting's start posts a macOS notification: the Event's title (or "(No title)"), "Starting now. Record it in Crumble?", and a Record button. Crumble never records on its own; only a click on Record starts a Recording. Nothing posts while Crumble is not running.
- `crumble_calendar::suggestions::due` decides. An Event is due when it is timed, in a shown Calendar (not Disabled, its Account neither Disabled nor Hidden), has a join link or a Participant who is not the user, started no more than 5 minutes ago, is not the Event being recorded, and was not suggested earlier in this run. Declined and cancelled Events never reach it, as EventKit reads leave them out.
- An Event is told apart by `suggestions::key`: its series UID and occurrence once it has a UID, else `Event::id` ([ADR 0004](../adr/0004-event-identity-for-notes.md)). The key is the notification's identifier, so a moved occurrence is not suggested twice and a click finds it again.
- A `CalendarEvents` entity of its own holds today's Events in the shown Calendars, read off the main thread like the Calendar page's, again when the day, the shown Calendars or EventKit change. The minute tick that redraws Week view runs at the start of each minute and checks for Events due; so does each read of today's Events. An Event is caught within a minute of its start, and up to 5 minutes late, as after the Mac wakes.
- The first Suggestion asks macOS for permission to notify, so the prompt comes with a meeting rather than at launch. A denial is not asked again; the Event still counts as suggested.
- Clicking the notification opens the Event's page with its Note. Clicking Record opens it and does what the empty state's Record does: makes the occurrence's Note and records it. If the occurrence has a Note already, Record uses it, and if that Note has a Recording, Record only opens it, as a Note has at most one Recording. While another Recording runs, Record only opens the page, where the disabled Record button names the Note being recorded. A click that launches Crumble waits for today's Events to be read first. An Event no longer among today's, as after midnight, opens the Agenda page instead.
- The notification center's delegate is set while the app finishes launching, so a click that launches Crumble is heard. It shows the banner while Crumble is frontmost too, and hands each click to the root view through a channel.
- Debug builds bind ⌘⌥⇧S to post a Suggestion for an invented "Sample meeting" starting now, so the banner and both clicks can be tried without a real meeting. Release builds have neither the binding nor the action.
