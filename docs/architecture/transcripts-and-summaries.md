# Transcripts and Summaries

Part of the [native architecture](native.md): Transcripts and Summaries.

## Transcript

Transcript and Model are defined in [CONTEXT.md](../../CONTEXT.md); the design is [ADR 0006](../adr/0006-on-device-transcription-via-swift-bridge.md) for Apple's Model, [ADR 0010](../adr/0010-local-models-through-transcribe-cpp-and-handys-list.md) for Local Models, and [ADR 0008](../adr/0008-remote-transcription-and-audio-consent.md) for remote ones.

- When Stop ends a Recording and its length is stored, its Note is transcribed with the Transcription Model, asking for consent when needed; a length kept in memory after a failed save is transcribed once it saves, unless that needs consent. That is the only Transcript made on its own, for every Model. A Recording stopped by quitting, closing the window or deleting its Note is not transcribed then, nor at the next launch, nor when a Model or Language is picked: its Transcript tab offers to transcribe it, and Settings › Transcription offers Transcribe all. A Note whose last attempt failed this run keeps its error and Try again, until that Provider's address, Transcription Model or key changes, or another Transcription Model or Language is picked. A server whose address has no `http://` or `https://`, or cannot be read, is not offered and transcribes nothing; its Notes' Transcript tab points to Settings. Transcribe with, Transcribe again with…, Transcribe all and Try again queue a Note with a Provider. One job runs at a time, first come first, on GPUI's background executor; it sends its progress and result over a channel, and the result is stored through `Notes` on the main thread. Deleting the Recording or the Note drops its job's result. A call into Swift, a Local Model's worker or an upload cannot be stopped, so a job already running finishes unseen, and the next one waits for it.
- A job transcribes in the Language picked in Settings, else the Mac's current locale (`Locale.current`), and transcribes `mic.aac` and `system.aac`, whichever exist, each on its own, then merges their segments in time order.
  - With Apple's Model, if that locale's speech model is not installed it downloads it first, Apple's shared on-device asset of a few hundred MB per language. The Model is stored as "Apple SpeechAnalyzer".
  - With a Local Model, Crumble starts itself again as a worker, `crumble --transcription-worker <Model file> <VAD file> <language> gpu <tracks>`, so a crash in it cannot end the app or a Recording. The worker loads the Model with transcribe.cpp on Metal and decodes each track to 16 kHz mono through ExtAudioFile. Whisper and the Parakeet family get a track whole and give their own segment times; every other Model, and one whose times are missing, gets it cut in the middle of pauses Silero VAD finds, into chunks of 5 to 40 s near 30 s, each chunk one segment when the Model gives no times. It prints progress and segments on stdout, one per line. A worker killed by a signal, as a GPU fault ends one, is run once more on the CPU. The language is the locale's ISO 639 code, or the Model's own guess for Detect automatically; a Model that does not list it fails with "This Model doesn't transcribe <language>. Pick another Language or Model in Settings.". The Model is stored as its name, and its Provider as `local`.
  - With the OpenAI-compatible server, each track is cut between ADTS frames into pieces under 20 MB, repackaged into M4A by `afconvert` in a temporary folder deleted afterwards, and sent to `POST {address}/audio/transcriptions` with the Transcription Model, `verbose_json` and the locale's language. Progress counts pieces done. The Model is stored as its name on the server.
- **Consent**: before audio first goes to a remote Model, an alert asks "Send this Recording to <Provider>?": "Crumble will upload the audio of this Recording to <host> to make its Transcript. You'll only be asked once for <model> on <host>." Send saves `(provider, model, host)` in `remote_audio_consents` with `acknowledged_at`, and transcribes; Don't send leaves the Recording untranscribed. It asks after Stop, on Transcribe with, on Transcribe again with… (after its replace question) and on Try again, whenever that key has no row; a loopback server is never asked about. The job checks again when it starts, and skips a Note whose Model or host changed since, and an older Recording queued while the server was local whose address is no longer local. On quit and window close nothing can ask, so the Note waits. Audio leaves the Mac only through this check, in `crates/ui/src/native_view/notes/consent.rs`.
- The Transcript tab shows, by state:
  - Waiting behind another job: "Waiting to transcribe…".
  - Downloading the model: "Downloading the speech model for English (United States)… 42%" with a progress bar.
  - Transcribing: "Transcribing… 42%" with a progress bar.
  - Not transcribed yet: a finished Recording no job took, as one stopped by quitting, or one the user did not agree to send. "Not transcribed yet" with "Transcribe with <Provider>", or with the Local Model's name, which transcribes that Note alone, after consent; while the picked Local Model is not downloaded, "Not transcribed yet. <Model> isn't downloaded." with Open Settings, which opens Settings on Local Models; or, while the picked server has no address or Transcription Model, "Not transcribed yet. Add the server's address and Model in Settings." with Open Settings, which opens Settings on Providers.
  - Failed: "Couldn't download the speech model." or "Couldn't transcribe this recording." for Apple's Model, a remote Model's error as a sentence, such as "Couldn't reach http://whisper.lan:8000/v1. Check that the server is running.", or "Couldn't save the Transcript.", with Try again; the error is logged, and never holds a key.
  - The locale cannot be transcribed: "Transcription isn't available for <language> on this Mac.", with no other language tried.
  - Done: "Transcribed by Apple, on this Mac", or "Transcribed by <Provider> · <model>" for a Local or remote one, in small muted text, then one line per segment: its start as `m:ss`, a link that seeks the player there; "You" for the microphone or "Others" for the Mac's sound; and the text. A Transcript with no segments says "No speech was heard."

## Summary

Summary, Model and Provider are defined in [CONTEXT.md](../../CONTEXT.md); the design is [ADR 0007](../adr/0007-summaries-and-model-providers.md).

- Once a Transcript is stored (after Stop, after recovering a Recording at launch, or after Transcribe again), its Note is queued to be summarized with the Summary Model, whichever it is, dropping any job for its old Transcript.
- Older Transcripts are summarized without being asked only by a Summary Model that runs locally: Apple's, or an OpenAI-compatible server whose address's host is `localhost`, `127.0.0.1` or `::1` (`crumble_remote::runs_locally`). At launch, after the Transcripts are queued, whenever a Summary Model is picked in Settings, and on Enter in or leaving an Address or Model field, such a Model, once it has what it needs (Apple's can run, the server has an address and a Model), gets every Note whose Transcript has speech but no Summary, each queued with that Provider, so a remote Model picked while they wait never gets them; one whose server's address stops being local while it waits is dropped and offered in its tab instead. A Note whose last attempt failed this run is left with its error and Try again, until that Provider's fields or key change or its Test passes, which also starts the backfill. Claude, or a server elsewhere, gets an older Transcript only when the user presses Summarize with in that Note's Summary tab, one Note at a time. Summarize again with… and Try again queue it with a Provider. One job runs at a time, first come first, on GPUI's background executor, and the Summary is stored through `Notes` on the main thread. Deleting the Recording or the Note drops its job's result. A Transcript with no speech, no segment or only empty ones, is not summarized and shows no Summary tab.
- A job uses the Provider it was queued with, else the Summary Model picked in Settings, else Apple's when it can run. It reads the key from the Keychain when it starts and builds the `Summarizer` with the Settings fields; Apple's fails with why when it cannot run, as "Apple isn't available: Turn on Apple Intelligence in System Settings." A remote Summary cut short by the Model's token limit fails rather than being kept; Apple's model does not say when it stops short, so its answers, capped at 1,000 tokens each, are kept as they come. The Model reads the Transcript as `You: …` and `Others: …` lines. Apple's reads it in parts that fit its 4k-token context; the others get it whole.
- The Summary tab shows, by state:
  - Waiting behind another job: "Waiting to summarize…".
  - Summarizing: "Summarizing… 40%" with a progress bar, or "Summarizing…" with a moving bar until the Model reports progress. Remote Models report only when done.
  - Not summarized yet: a Transcript with speech that no job took, as one older than a remote Summary Model. "Not summarized yet" with "Summarize with <Provider>", which queues that Note alone.
  - No Summary Model: "No Summary Model picked. Choose one in Settings." with Open Settings, which opens Settings on Summary.
  - Failed: the error as a sentence, such as "Claude didn't accept the API key. Check it in Settings.", with Try again; the Summary the Note already had stays below it. The error is logged, and never holds a key.
  - Done: the Summary rendered as Markdown with GPUI Kit's `TextView`, selectable, then "Summarized by <Provider> · <Model>" in small muted text.
