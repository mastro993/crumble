# Notes

Part of the [native architecture](native.md): Notes and Quick notes.

## Notes

Note, Quick note and Memo are defined in [CONTEXT.md](../../CONTEXT.md).

- One Note detail view, the Agenda page's content area, shows the Note of the selected Agenda row or Event: a Quick note itself, or the Event occurrence's one Note, if it has one. It reads it again whenever what it shows changes, synchronously on the main thread; a failed read is logged, shows nothing, and is tried again on a later redraw; an Event that moves is still the same occurrence, found by its series UID and occurrence, so its Note stays as it is. `Notes` is owned by the root view beside `Store`.
- At the top is the Note's title, large and editable in place. While it is empty its placeholder is the Event's title, kept current as the Event changes, or "Quick note". Enter or leaving the field saves it, and an empty title is saved as none; a failed save is handled as the Memo's is below. Below it, in muted text, is when the Event happens, as the details card writes it, or when the Quick note is listed: its Recording's start, else when it was made. An Event with no Note shows its title as plain text.
- Below the title is a card with a tab bar, then the tab. The tabs are Summary once the Note has a Summary, one is waiting, being made or failed, or its Transcript has speech (see Summary), then Memo, then Transcript once the Note has a Transcript, one is being made, or a finished Recording whose length is stored (see Transcript). The bar's trailing side holds the Recording controls (see Recording). The tab the user picks stays picked across Notes while the shown Note has it; otherwise the first tab shows. The Memo is a field that grows with its text. It is saved 500 ms after typing pauses, at once when it loses focus, before another row shows, and when the window closes or the app quits. A failed save is logged, says "Couldn't save" under the card, and keeps the text in memory, which is shown again in place of the stored Memo and tried again on every later save of any Note, until it is written. While any still fails, closing the window asks first in an alert, as closing loses it; quitting does not ask. An Event with no Note shows "No note yet" in the card with a New note button, which makes the occurrence's Note, shows it, and focuses its Memo, and a Record button, which does the same and starts recording it. If the occurrence has a Note by then, as when another Calendar's copy of the Event made one, that Note shows instead of a second.
- The Note actions button, a "…" icon, sits on the right of the page header while there is a Note. Clicking it opens a menu below it (see Context menus) with Transcribe again with… (Transcribe with… before there is a Transcript) and Delete recording when the Note has a Recording that is not running (Transcribe again with… only while no Transcript of it is waiting or being made), a submenu of the Providers ready to transcribe with a check on the one that made the Transcript; Summarize again with… (Summarize with… before there is a Summary) when the Note has a Transcript with speech and no Summary of it is waiting or being made, a submenu of the Providers ready to summarize with a check on the one that made the Summary; and Delete note. Each submenu lists the Providers in Crumble's order, Apple's, then the picked Local Model by name, then the remote ones, and offers a remote Provider only while it is ready for that job (see Readiness in [Providers](providers.md)). The Summarize submenu leaves out Apple's when it cannot run, and the row is left out when none is ready; the Transcribe submenu always has Apple's, and the Local Model while one is picked and downloaded. Transcribe again with… asks first when there is a Transcript, as the new one replaces it, then for consent when needed (see Transcript). Delete recording asks first in an alert, then deletes the audio, clears the Recording, and deletes its Transcript and Summary. Delete note asks first in an alert, since nothing brings a Note back, and deletes its Recording's audio too, stopping it if it is running. A deleted Event's Note leaves the card empty again; a deleted Quick note's row leaves the Agenda and the selection clears.

- `crates/notes` keeps Notes in the `notes` table of `crumble.sqlite3`, through its own connection beside the one `crates/store` keeps. The file runs in WAL mode with a 5 s busy timeout, so one connection reads while the other writes. If the file cannot be opened, Notes use an in-memory database for that run and are not kept; their Recordings go to a temporary folder, deleted when `Notes` is dropped as the app quits.
- Each row has a UUID v7 `id`, an optional `title`, the `memo`, and `created_at`, `updated_at` and `deleted_at` as RFC 3339 UTC text to the millisecond. Every change sets `updated_at`. Deleting a Note first deletes its Recording's folder, then sets `deleted_at`, and every read skips it; a deleted Note cannot be edited or brought back. Its row stays only as a tombstone for sync, keeping its id and timestamps: the transaction that sets `deleted_at` also clears its title, Memo, Event key and snapshot, Recording, Transcript and Summary columns, and deletes its Transcript segments. A folder that cannot be deleted leaves the Note, or its Recording, in place to try again, so no audio is left behind unreachable.
- A Note attached to an Event keeps the Event's key, `event_series_uid` and `event_occurrence`, and a snapshot of its `event_title` and `event_start` ([ADR 0004](../adr/0004-event-identity-for-notes.md)). An occurrence and a start are stored as `2026-10-13` for an all-day one or `2026-10-13T07:00:00Z` for a timed one. A Quick note has all four `NULL`.
- An Event occurrence has at most one Note, shared by every Calendar that shows it: the Note whose key matches it (the same UID, and the same occurrence or none for both), else the oldest whose snapshot matches its title and start and that has no UID or the Event's own. The snapshot finds a Note made before the Event synced, or one whose occurrence key changed; it never matches a Note keyed to another UID, so two Events with the same title and start keep their own Notes. Making a Note for an Event that has one returns that Note. A unique index on `(event_series_uid, IFNULL(event_occurrence, ''))` over live keyed Notes refuses a second one; the `IFNULL` is there because a UNIQUE index tells NULLs apart. Reading never rewrites a stored key, and a Note whose Event is gone is kept.
- Quick notes are listed newest first by `COALESCE(recording_started_at, created_at)`, the expression the `notes_quick` index is on.
- A Recording is `recording_started_at` (RFC 3339 UTC, to the millisecond) and `recording_duration_ms`, both `NULL` without one. A start with no length is a Recording still running, or one a crash cut short.
- A Transcript is `transcript_provider` (the Provider's id, such as `apple`, `local`, `openai` or `openai-compatible`, any id `crumble_remote::Provider` gives, with no `CHECK` since migration 000011 renamed `openai` to `openai-compatible`), `transcript_model`, `transcript_locale` and `transcribed_at` on the Note, all `NULL` without one, and its rows in `transcript_segments`: `note_id`, `track` (`mic` or `system`), `start_ms`, `end_ms` and `text`, read in `start_ms` order. `Notes::set_transcript` replaces a Transcript in one transaction, hard-deleting the old segments, and needs a finished Recording. Deleting the Recording or the Note deletes its Transcript.
- A Summary is `summary` (Markdown), `summary_provider` (the Provider's id, such as `apple`, `anthropic` or `openai-compatible`; migration 000011 renamed `claude` to `anthropic`), `summary_model` and `summarized_at` on the Note, all `NULL` without one. `Notes::set_summary` replaces it and needs a Transcript. Storing a new Transcript, deleting the Recording, and deleting the Note clear it in the same transaction. `Notes::unsummarized` lists the Notes whose Transcript has at least one segment with text and no Summary.
