# Providers

Part of the [native architecture](native.md): remote Providers, their API keys, and the Models each job uses.

## Providers

Provider, Model and Intelligence Model are defined in [CONTEXT.md](../../CONTEXT.md); the design is [ADR 0011](../adr/0011-remote-providers-as-a-registry.md), with [ADR 0007](../adr/0007-summaries-and-model-providers.md) for Summaries and [ADR 0008](../adr/0008-remote-transcription-and-audio-consent.md) for remote Transcripts and consent.

- `crumble-remote` describes each remote Provider in one `Remote` descriptor, a file each in `crates/remote/src/remote/`: its usual address, its API key's format and header, which jobs it does through which API, the Models it suggests, and the ping that checks a key. Settings, `crumble-summarize` and `crumble-transcribe` read only descriptors. `crumble-store` keeps what the user changed for each Provider in the `providers` table, and `crumble_store::secrets` its key in the Keychain. `crates/ui` holds which Providers have a key, the Models each listed this run, and the listings running or failed. Each Provider's dialog is its own entity, `ProviderDialog`, which sends every change to `NativeView` as a `ProviderDialogEvent`; `NativeView` keeps it through `Store` and `secrets`, then passes the dialog what Settings now holds.
- The remote Providers, in Settings' order: Anthropic, OpenAI, Google Gemini, ElevenLabs, OpenRouter, DeepSeek, xAI, then the OpenAI-compatible server, such as Ollama or LM Studio on the Mac or a Whisper server. ElevenLabs only transcribes; Anthropic and DeepSeek do not transcribe; the rest do all three jobs. ADR 0011 lists each one's key format, ping and default Models; its descriptor holds its usual address.

### The list

- Settings › Providers, under AI in the sidebar, lists the remote Providers in two cards, each in Settings' order: those set up, headed "Connected", then the rest, headed "Available". A card with no Provider is left out, so before any is set up only Available shows. A Provider moves between them as its key is saved or removed, or its address changes, even while its dialog is open. A row has the Provider's logo, 20 pt in a 28 pt rounded tile, its name in 15 pt, a muted 13 pt line under the name saying what it does, and a small outline button at the trailing edge: Set up until the Provider has a key, if it requires one, and an address requests can go to, then Edit. A mono logo takes the primary ink, a color one keeps its colors, and the server, which has no logo, shows one of Crumble's own icons.
- The line names the jobs the Provider does, joined by middots: "Intelligence" when it chats, which makes Summaries too, then "Transcription" when it transcribes, set up or not. Once set up, the server's adds its address's host, such as "localhost", then "On this Mac" at a loopback address: "Intelligence · Transcription · localhost · On this Mac".
- Only the button is clickable, and Tab reaches it; it reads out as "Set up <Provider>" or "Edit <Provider>". Rows are `settings-provider-{id}` and their buttons `settings-provider-{id}-edit`, by the Provider's id.

### The dialog

Set up or Edit opens the Provider's dialog, which sets up its key and address; its Models are picked in the Transcription, Summary and Intelligence sections (see [Settings](settings.md)). It is about 520 pt wide, fading in over the frosted backdrop every dialog uses, titled with the logo tile and the Provider's name. Its rows look like a Settings card's. Everything saves as it changes, so Done, Escape and the close button only close it, and a key still being checked as it closes is kept once its ping passes; Enter in the key or address field checks what it holds and never closes the dialog. As it opens, the key field takes the focus when the Provider requires a key and has none saved, else the server's address field while it is empty.

- **API key**, for every Provider that takes one. With no key saved, or after Replace, a masked field, with no reveal, says "Paste your <Provider> API key" ("API key (optional)" for the server). Under it:
  - While it is empty, a Get an API key link opens the Provider's key page in the browser; the server has none.
  - A key that cannot be the Provider's says why in red, before anything is sent: "These keys start with sk-ant-.", "This key looks incomplete. Paste it again.", "A key has no spaces. Paste it again.", or for another kind of key the Provider issues, such as "This is an Admin key, which can't make Summaries. Use an API key.", or another Provider's key that starts the same way, such as "This is a DeepSeek key."
  - A key that looks right is pinged after typing pauses for 400 ms, or at once on Enter or paste, showing "Checking…" with a spinner. A newer edit drops the running check, and so does an edit of the address: a finished address, with Enter or by leaving the field, pings the key being typed again, there, so a key never goes to an address half typed.
  - Once the ping passes, the key goes into the Keychain and the field empties; the Models it listed are kept for this run, the Provider's failed Summaries and Transcripts are forgotten, the Summary backfill starts (see Summary in [Transcripts and Summaries](transcripts-and-summaries.md)), and the row says "Saved in Keychain · Checked" in green, until the address changes; the footer's result about the old key goes, and the dialog takes the field's focus, so Escape still closes it. A Keychain write that fails says "Couldn't save the key." in red.
  - A failed ping shows its sentence in red, such as "OpenAI didn't accept this key.", keeps the text so it can be fixed, and offers Try again.
  - With a key saved, the row says "Saved in Keychain" with Replace and Remove. Replace empties the field, shows and focuses it, and the saved key stays until a new one passes its check. Remove deletes the key without asking, forgets the Provider's failures and the Models it listed, drops the footer's result, and shows the empty field, focused; a Keychain delete that fails says "Couldn't remove the key." in red.
- **Address**: a field whose placeholder is the Provider's usual address, described "Leave empty to use <address>."; the server's placeholder is `http://localhost:11434/v1`, described "Where the server's API is, such as Ollama's or LM Studio's." Each keystroke saves it, trimmed, empty for the usual one, drops the listed Models and any check result, and forgets the Provider's failures. Enter, or leaving the field after a change, checks the Provider at that address, as Check again does, when it has a key or needs none. An address requests cannot go to says why in red, such as "Start the server's address with http:// or https://.", and nothing is sent to it.
- For the OpenAI-compatible server at a loopback address, a muted line at the bottom: "This server is on this Mac."
- The footer has Check again, while a key is saved or none is needed, and Done. Check again pings with the saved key, or none, at the address as typed; it is disabled while that address cannot be sent to or a check runs. Its result, and that of a finished address's check, shows at the footer's leading edge until the key is saved or removed or the address changes: "Checking…" with a spinner, then "Checked" in green or the error in red. A passed check keeps the Models it listed for this run and starts the Summary backfill.

### Keys and the ping

- A key is checked against the Provider's format as it is typed or pasted, spaces around it ignored, and then pinged: `crumble_remote::ping` GETs a key's details or the Models list, within 20 s, so it spends no tokens. A refused key, an address with nothing behind it or that redirects, too many requests or a Provider's own problem each have a sentence. A key that may use Models but not list them, answered with 403, passes, and its Models are typed into the sections' Model selects; Gemini's keys have no such limits, so there a 403 refuses the key with Google's reason, such as a key reported as leaked. Anthropic's workspace, personal and service account keys all pass the format. An Anthropic key made for more than one workspace is refused with "This key isn't limited to one workspace. Make a key for one workspace.", as its requests would need a workspace header Crumble doesn't send. A passed ping does not prove the account has credit; that shows on the first job, as the Provider's error.
- Keys are kept in the login Keychain, service `io.github.mastro993.crumble.api-keys`, account the Provider's id. At launch Crumble first moves keys saved by earlier builds under the service `io.github.mastro993.crumble` (`claude` to `anthropic`, `openai`, the OpenAI-compatible server's, to `openai-compatible`), then reads which Providers have a key from the items' attributes, without reading any key. A key is read only when a check or job starts, goes only into its request's header, and is never stored in SQLite, logged, put in an error, or shown; a Provider's message that repeats it has it taken out. No request follows a redirect, so a key never reaches another host.

### Addresses and Models

- `providers` has a row per remote Provider the user changed: `id`, `base_url`, `summary_model`, `transcription_model` and `intelligence_model`, each `NULL` for the Provider's own default. A row back to all defaults is deleted. Requests go to the saved address, else the Provider's usual one; the server has none until one is given.
- The OpenAI-compatible server at a loopback address, `localhost`, `127.0.0.1` or `::1`, counts as on the Mac (`crumble_remote::runs_locally`): it summarizes older Transcripts without being asked, and gets audio without consent. A company's API counts as remote at any address, even through a proxy on the Mac, which passes what it reads on to the company. Any other address counts as remote, even one that is this Mac.

### Readiness

- A remote Provider is ready for a job when it does the job, has a key if it needs one, an address requests can go to, and a Model for that job. Apple's Model is ready for Summaries and Intelligence when it can run, and always for Transcripts; a Local Model when it is picked and downloaded.
- A remote Provider is set up once it has a key if it needs one and an address requests can go to. The Provider selects of the Transcription, Summary and Intelligence sections ([Settings](settings.md)) offer the remote Providers set up for their job, so the Model select under them can give one a Model; the Note actions submenus ([Notes](notes.md)) offer those ready for their job. Each is titled with its name. Apple's row in the Summary and Intelligence selects is disabled while its Model cannot run, and the Summarize submenu leaves it out. A picked Provider that stops being set up, such as one whose key was removed, stays picked, as a row described "Not set up"; its jobs say why, such as "Not transcribed yet. Finish setting up xAI in Settings." with Open Settings, which opens Providers.
